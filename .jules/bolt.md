## 2026-03-09 - Avoid try/catch for Expected Missing Files
**Learning:** In Node.js, `fs.readFileSync` throws an `ENOENT` error when a file is missing. Generating Error objects and unwinding the stack trace is significantly slower (around 10x slower) than calling `fs.existsSync`. When checking multiple fallback paths where missing files are the common/expected path, throwing and catching errors creates a measurable bottleneck.
**Action:** When a file is frequently expected to be missing (e.g., checking multiple configuration or fallback paths), use `fs.existsSync` to fail fast and cheaply instead of relying on a `try/catch` block around `fs.readFileSync`. Always retain the `try/catch` around the read operation to safely handle other errors (like permissions, lock issues, or invalid JSON).
