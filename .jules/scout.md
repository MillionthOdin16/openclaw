## 2026-03-31 - Model Fallback Pattern
**Defect Pattern:** Volcengine Coding Plan's quota limits throw HTTP 429 with errors matching `/exceeded.*quota|quota.*exceeded/i` but get classified as standard transient `rate_limit` by OpenClaw's failover handler. This causes the fallback chain (to models like Qwen) to be completely bypassed, creating infinite retry loops because the error behaves like a persistent billing error (quota exhaustion).
**Local Impact:** `src/agents/pi-embedded-helpers/failover-matches.ts` places "exceeded your current quota" and "quota exceeded" into `rateLimit` list, so `isRateLimitErrorMessage` matches. They need to be matched as `billing` errors instead so the agent triggers the fallback logic instead of infinitely retrying. The issue #58442 reveals this exact failure pattern happens in our local fork as well.
**Review Strategy:** Check the definitions in `ERROR_PATTERNS` within `src/agents/pi-embedded-helpers/failover-matches.ts` and related failover logic files (`failover-error.test.ts`, `isbillingerrormessage.test.ts`) when scanning for similar misclassification of persistent vs transient failures.
