## 2026-03-01 - [DOM-based HTML Escaping leaves attributes vulnerable to XSS]
**Vulnerability:** A custom `escapeHtml(text)` function used DOM instantiation (`div.textContent = text; return div.innerHTML;`) which correctly escapes `<` and `>` but leaves `"` and `'` unescaped, leading to Cross-Site Scripting (XSS) when output is embedded in HTML attributes.
**Learning:** Using DOM-based escaping functions provides an incomplete sanitization profile for HTML encoding as it misses quote characters. While it might prevent elements from being injected, it leaves applications fully vulnerable when that content is rendered inside an attribute boundary (e.g. `<img src="data" class="${unsafe_class}">`).
**Prevention:** Always use explicit string replacement mechanisms (e.g. `text.replace(/&/g, '&amp;').replace(/</g, '&lt;').replace(/>/g, '&gt;').replace(/"/g, '&quot;').replace(/'/g, '&#039;')`) or robust established libraries like DOMPurify or marked when handling generic HTML escape requirements to ensure broad safety across all contexts.
